# PVT behaviour of real gases

A Chemical Engineering Thermodynamics project. Python package: `realgas-ml` 0.2.0.

A Python property-prediction package for 15 pure gases, expanded from 50 to **65,536 training states per gas** (983,040 total; 1,310.72 times the previous count). It predicts compressibility factor Z, molar/total volume, density, molar enthalpy and entropy, total H and S, and pressure from temperature and molar volume.

## Install and use

Python 3.11 or newer is required. Unzip, open a terminal in `realgas_ml`, then run:

```sh
python -m pip install .
python -m realgas_ml.cli --list
python -m realgas_ml.cli --gas CarbonDioxide --T 400 --P 2000000 --n 2
python example.py
```

```python
from realgas_ml import GasModel
m = GasModel("Nitrogen")
r = m.predict(T=400, P=1_000_000, n=2)
print(r["V_m3"], r["H_J"], r["S_J_K"])
print(m.pressure(T=400, v=r["v_m3_mol"]))
```

Inputs: T in kelvin, P in pascals, n in mol (default 1). Outputs: `v_m3_mol`, `V_m3`, `rho_kg_m3`, `h_J_mol`, `s_J_mol_K`, `H_J`, `S_J_K`, and dimensionless `Z`. Gas names are case sensitive. Inputs must be finite and within the trained domain. Scalar API is preserved from 0.1.0.

## What changed

- 256 by 256 training grid in normalized temperature and log-pressure for each gas.
- 512 independent validation, 2,048 interior test and 256 boundary test states per gas. Total: 7,680 validation and 34,560 test states; none used for fitting.
- Scalable local quintic radial-basis-function regression with 48 nearest training neighbors, rather than full Gaussian processes. The solver is **SciPy RBFInterpolator**, wrapped as a **scikit-learn estimator**, with scikit-learn output standardization. This is deterministic kernel interpolation, not a Gaussian process or neural network. No posterior uncertainty is claimed.
- Multi-output fitting of log(Z), h and s. Positive Z/volume follow from exponentiation. H/S conventions are unchanged.
- Uses each source EOS's fitted molar gas constant for v = Z R_fluid T/P. This corrects a small volume convention mismatch in the first version, which used one universal constant for all EOSs.
- Same-state comparison with the actual original saved 50-point GPR models; includes the original volume convention in baseline errors. Both data density and model family changed, so improvement cannot be attributed to data count alone.

## Data provenance and limits

**All new training labels are generated by CoolProp HEOS 8.0.0 reference equations of state. They are not experimental measurements.** A direct attempt to download the NIST ThermoML experimental JSON returned HTTP 403; no experimental data were incorporated. Additional generated points improve approximation of the EOS, not its experimental fidelity.

Reliable source: Bell, Wronski, Quoilin and Lemort (2014), Pure and Pseudo-pure Fluid Thermophysical Property Evaluation and the Open-Source Thermophysical Property Library CoolProp. https://doi.org/10.1021/ie4033999

CoolProp documentation: https://coolprop.org/coolprop/HighLevelAPI.html

Fluid-specific EOS citation keys and URLs, source version, ranges and gas constants are recorded in `metadata.json`. Source reference states are per-fluid DEF conventions: these are not formation enthalpies or a common third-law entropy convention. Use h/s differences within the same fluid; these values do not support reaction-energy calculations across species.

Pressure domain: **0.1–5 MPa**. Temperature ranges below are the original gas-specific ranges above critical temperature. This update does not broaden physical coverage. No liquid, two-phase, mixtures, cryogenic or near-critical behaviour. Predictions outside the domain are rejected.

The three fitted properties do not enforce Maxwell relations, consistent derivatives or other fundamental-EOS identities. Local neighbor changes can affect high-order derivatives. Do not use these models to calculate derivative properties or near-critical behaviour. Monotonic volume checks cover a finite verification grid and do not prove global thermodynamic stability.

Very small reported errors quantify interpolation against the generating EOS. They are not physical uncertainty estimates and do not imply comparable accuracy against experiments. In some cases the interpolation error is far below the uncertainty of the reference EOS; additional sampling then has little physical benefit.

## Why stop at 65,536 states per gas?

Learning curves compare 1,024, 4,096, 16,384 and 65,536 points on a separate 512-point validation sample per gas. The largest tested size is retained to prioritize data density as requested. All candidates use the same fixed kernel and neighbor count. More generated values can be obtained, but storing additional almost redundant EOS samples has diminishing value once surrogate errors are already negligible. 65,536 is a practical chosen budget, not a limit on data availability. Final tests are evaluated only for reporting, not tuning.

## Reproduce and inspect

```sh
python -m pip install '.[train,test]'
python train.py
python -m pytest -q
python export_data.py --gas Nitrogen --output nitrogen.csv.gz
```

Run `python train.py` from the project folder to regenerate all models and metrics. Seed: 20261016 plus stable gas index. SciPy 1.17.0 and scikit-learn 1.8.0 are pinned for serialized-model compatibility; use a virtual environment for installation. The `--gas` option is for diagnostics and does not replace full metadata. Load only the supplied trusted joblib files.

Each `data/<gas>_dataset.npz` contains `{train,validation,test,boundary}_X` and corresponding `_y` arrays. X columns are `(T-Tmin)/(Tmax-Tmin)` and `ln(P/Pmin)/ln(Pmax/Pmin)`; y columns are `ln(Z), h[J/mol], s[J/mol/K]`. `export_data.py` reconstructs SI states and exports inspectable CSV, optionally gzip-compressed. No CoolProp is required for predictions or export; it is needed to regenerate labels and run source-EOS comparison tests.

The original data, metadata and model files are preserved under `baseline/` for reproducibility. `validation.json` contains same-test baseline/improved/boundary metrics, and `learning_curve.json` contains validation-only sample-size results. Training data are not mixed with test or validation states.
